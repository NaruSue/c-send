# c-send PWA版 設計書

## 1. 目的

c-send PWA版は、定型文をスマートフォンから素早くコピーするためのWebアプリである。

- iPhoneを主な利用端末とする
- バイナリを導入できない環境でも、HTTPSで公開されたページを開いて利用できる
- ホーム画面へ追加して、アプリのように起動できる
- ネイティブ版およびHTA版の全機能は再現しない

## 2. 基本方針

- スマホ縦持ち・全画面表示を基本とする
- データは端末内のIndexedDBへ保存する
- カテゴリは設けず、タグ・検索・使用頻度で目的の定型文を探す
- すべての操作はタッチ操作で完結させる
- 一般的なアプリ設定画面は設けない。ただし、API定義・資格情報を管理するAPI設定画面は設ける
- iOSの制約で自動化できない操作には、手動操作の導線を用意する
- JSONデータ形式は、ネイティブ版・HTA版と共通の [共通JSONデータ形式仕様](../../../docs/data-file-spec.md) を参照する

## 3. 配布構成

PWAとして公開する際は、`scripts-ver/pwa` 配下を同じ公開ディレクトリへ配置する。

本番公開先はGitHub Pagesとし、公開URLは次とする。

- `https://narusue.github.io/c-send/`

```text
scripts-ver/pwa/
├─ index.html              # アプリ本体（HTML / CSS / JavaScript）
├─ samples.json            # 初回起動用サンプル
├─ manifest.webmanifest    # PWAマニフェスト
├─ service-worker.js       # オフライン用キャッシュ
├─ apple-touch-icon.png    # ホーム画面・画面内アイコン
├─ c-send.ico              # ブラウザ用アイコン
├─ .nojekyll               # GitHub Pages用
├─ readme.md               # 利用者向け説明
└─ docs/design.md          # 本設計書
```

## 4. 画面仕様

### ヘッダー

- タイトル行は画面上部に固定表示する
  - 一覧をスクロールしても、アプリ名と主要操作を常に確認できるようにする
  - コンテンツがタイトル行の下へ入り込まないように、固定行の高さ分だけ上部の表示領域を確保する
- 左上: c-sendアイコン
  - タップすると、次のメニューを表示する
    - 使い方
    - 区切り線
    - ファイルから追加
    - URLから追加
    - 区切り線
    - バックアップ
    - リストア
    - 区切り線
    - API設定
    - 区切り線
    - バージョンチェック
  - メニューは「使い方」「ファイルから追加」「バックアップ／リストア」「API設定」「バージョンチェック」の5グループに分け、グループ間に区切り線を表示する
  - `使い方` を選択すると、現在表示している使い方の説明を表示する
  - `ファイルから追加` を選択すると、共通JSONファイルを選択して既存データへ追加する
  - `URLから追加` を選択すると、URL入力後に共通JSONを取得して既存データへ追加する
  - `バックアップ` を選択すると、端末内へバックアップファイルを書き出す
  - `リストア` を選択すると、端末内のバックアップファイルを選択して読み込む
    - 定型文バックアップ
    - 設定バックアップ
  - `バージョンチェック` を選択すると、公開URLの最新版を確認し、更新があればキャッシュを更新して再起動する
- 中央: アプリ名とPWA版バージョン
- 右上: 家と追加記号のアイコン
  - ブラウザで開いている時だけ表示する
  - タップすると、ホーム画面への追加方法を表示する
  - standaloneモード（ホーム画面から起動）では非表示にする

### 一覧

- 検索欄でタイトル・本文・タグを検索する
- 検索欄に文字が入力されている時だけ、入力欄の右端にクリアボタン（×）を表示する
  - クリアボタンをタップすると検索文字をすべて削除する
  - 削除後は検索結果を初期状態へ戻し、検索欄のフォーカスとキーボード表示を維持する
  - 検索欄が空の場合はクリアボタンを表示しない
- タグチップをタップして絞り込む
- コピー回数の多い順、同数時は最後に使った日時の新しい順で表示する
- 各行には種別表示付きのタイトルとタグを表示する
- `plain` は種別表示なし、`template` はタイトル先頭に `[T]`、`counter` はタイトル先頭に `[C]` を表示する
- 種別表示は表示上の接頭辞であり、`name` の保存値には含めない
- メニューから編集・削除する

### バックアップ・リストア

- バックアップは、IndexedDBに保存している定型文データを共通JSON形式で端末内へ書き出す
- バックアップには、定型文・タグ・コピー回数・最終コピー日時を含める
- バックアップファイルには、共通JSON形式の識別子・形式バージョン・メタデータを含める
- リストアは、端末のファイル選択機能で共通JSON形式のバックアップを選択して読み込む
- 読み込み前に、既存データを置き換えることを確認する
- リストアは既存データの全置換とし、重複統合は行わない
- 共通JSON形式、必須項目、データ件数を検証し、不正なファイルは読み込まない
- 読み込みに成功した場合は、一覧を再読み込みして復元結果を表示する
- バックアップ・リストアでデータを外部サーバーへ送信しない

#### 設定バックアップ

- API定義とPWA固有設定をバックアップするため、定型文バックアップとは別の「設定バックアップ」を提供する
- 設定バックアップの対象には、ネイティブ版と共通のAPI設定JSON、API Action定義、API token／Bearer token、Basic認証のID／PASSを含める
- API設定JSONにはAPI tokenなどの機密情報を直接保存しない。API定義と機密資格情報はIndexedDB上で別のストアへ保存する
- 設定バックアップの作成時は、利用者が任意のパスワードを入力する。パスワードは保存せず、確認入力が一致しない場合は作成しない
- パスワードからWeb Crypto APIのPBKDF2で鍵を導出し、AES-256-GCMでバックアップペイロードを暗号化する
- 暗号化ファイルには、バックアップ形式識別子、形式バージョン、KDF名・反復回数・salt、暗号化方式・iv、暗号文、作成日時を含める。パスワード自体と導出鍵は含めない
- リストア時はパスワードから鍵を再導出し、認証タグの検証に成功した場合だけ復号・JSON検証・IndexedDB更新を行う
- パスワード不一致、改ざん、形式不正、復号後のJSON不正の場合は、既存のAPI定義・資格情報を変更せずエラーにする
- 設定リストアは既存のAPI定義と資格情報の全置換とし、既存設定との自動統合は行わない。実行前に全置換であることを確認する
- 設定バックアップ・リストアのファイル名や画面表示にはAPI tokenなどの機密情報を含めない

### データ追加

- `追加` は既存データを置き換えず、読み込んだ項目を現在の一覧へ追加する。ただしタイトルと本文が一致する項目は重複追加せず、既存項目を更新する
- `ファイルから追加` は、端末のファイル選択機能で1つ以上の共通JSONファイルを選択して読み込む
- ファイルから追加した項目には、取り込んだファイル名を `sourceName` として保存する
- `URLから追加` は、入力したURLから共通JSONを取得して読み込む
- URLから追加した項目には、取り込んだURLを `sourceName` として保存する
- タイトルと本文が既存項目と一致する場合は新規追加せず、タグを重複なしで統合する
- 重複項目を更新する場合は、今回のファイル名またはURLを `sourceName` として上書きする
- URLから読み込んだデータはPWA側で追加のみ行い、元URLの内容は変更しない
- ファイル形式、必須項目、データ件数を検証し、不正なファイルやURLデータは追加しない

### コピー確認

1. 一覧行をタップすると、本文をクリップボードへコピーする
2. 成功時はコピー済みの本文を確認画面に表示する
3. 確認画面をタップすると閉じ、一覧へ戻る

誤って似た名前の項目をタップしても、コピー内容を確認してから別の項目を選び直せるようにする。

### 追加・編集

- 右下の `＋` ボタンで追加画面を開く
- タイトルは任意。未入力時は本文の先頭20文字程度をタイトルにする
- タグはカンマ区切りで複数入力できる
- 本文は複数行を許可する
- タイトル・タグ・本文を編集できる
- 本文入力欄の下に、`plain text` と `template` のラジオボタンを表示する
- 新規追加時は `plain text` を既定選択とする
- 編集時は、保存されている `mode` に応じて選択状態を復元する
- `counter` は当面ラジオボタンの選択肢として表示せず、保留とする

## 5. iPhoneでの利用

### PWAとして追加する方法

Safariでページを開き、右上の家アイコンをタップする。

1. Safari下部または上部の共有ボタンをタップする
2. `ホーム画面に追加` を選ぶ
3. `追加` をタップする

ホーム画面から起動した場合はPWAのstandaloneモードとなり、右上の追加アイコンは表示しない。

### クリップボード

- 一覧からのコピーは、行のタップをユーザー操作として実行する
- `＋` ボタンをタップした時、クリップボードのテキストを本文へ取り込むことを試みる
- iOSまたはブラウザの制約で読み取れない場合は、本文欄に手動で貼り付けてもらう
- 他アプリの起動や、他アプリへの自動貼り付けは行わない

## 6. データ保存

### IndexedDB

定型文はIndexedDBへ保存する。保存先がない場合は自動作成する。

- 定型文
- タグ
- コピー回数
- 最終コピー日時

API対応時は、定型文データとAPI設定・資格情報を論理的に分離して保存する。

- `items`: 定型文、タグ、コピー履歴
- `apiDefinitions`: ネイティブ版と共通のAPI設定JSON（`id`、`name`、`baseUrl`、`timeoutMs`、`authType`、`credentialId`、`keyConfig`、`actions`）
- `apiCredentials`: `credentialId`をキーとするAPI token／Bearer token、またはBasic認証のID／PASS
- `appMeta`: IndexedDBスキーマバージョン、PWA版設定情報

API資格情報の保存ルール:

- API token、Bearer token、Basic認証のID／PASSは`apiDefinitions`や定型文本文、ログ、URL表示へ保存・出力しない
- `credentialId`を資格情報の参照単位とし、同じ`credentialId`を指定したAPI定義から共有できる
- 資格情報は画面表示時に復元表示せず、入力欄が空の場合は既存値を維持する
- API定義を削除しても、同じ資格情報を参照する別のAPI定義があり得るため、資格情報は自動削除しない。資格情報の削除は明示操作で行う
- IndexedDBのデータは同一オリジン内で利用し、PWAのJavaScript以外へ送信しない。IndexedDB自体を端末暗号化の代替とはみなさない

保存失敗時はエラーを表示し、読み込みに失敗したデータを空データで上書きしない。

### 定型文形式

```json
{
  "name": "仕事：電車遅延で遅刻",
  "value": "電車遅延のため、◯分ほど遅れます。申し訳ありません。",
  "tags": ["仕事", "遅刻", "電車遅延"],
  "type": 0,
  "mode": "plain",
  "usageCount": 3,
  "lastUsedAt": "2026-07-25T12:00:00.000Z"
}
```

- `name`: 一覧へ表示するタイトル
- `value`: コピーする本文
- `tags`: 任意のタグ配列
- `type`: 現在は `0`（テキスト）のみ
- `mode`: `plain`、`template`、`counter` のいずれか。現行UIで選択できるのは `plain` と `template` とし、`counter` は保留する
- `usageCount`: コピー回数
- `lastUsedAt`: 最終コピー日時
- 最大件数: 設けない

## 7. API・AI連携

### 対応範囲

- PWA版は、ネイティブ版と同じAPI設定JSON仕様・認証方式・Action定義を使用する
- API設定JSONの必須項目、HTTPメソッド、Request／Response JSON、`{{value}}` の展開規則は、[API設定JSON仕様](../../../docs/api/config-spec.md) および [API機能設計書](../../../docs/api/design.md) に従う
- API定義はファイル同様のJSONとしてインポート・エクスポートできる。ただし資格情報はAPI定義JSONへ含めない
- 初期対応は`none`、`api-key-header`、`api-key-query`、`bearer`、`basic`とし、PWAのブラウザ`fetch`で実行可能なHTTP通信に限定する
- OAuth／SSO、WebSocket、multipartなど、ブラウザ側の追加実装やユーザー操作が必要な方式は初期対応の対象外とする
- API利用には各サービスのCORS許可が必要であり、CORSで拒否された場合は資格情報を含めず原因を表示する
- ネイティブ版で完成している共通JSON仕様・認証方式・Action実行を基準にPWA版へ実装する。ただし、資格情報の保存先とブラウザ通信の制約はPWA版の方式を使用する

### API定義と定型文

APIを利用する定型文は、共通定型文形式の`mode`と`options`でAPIとActionを参照する。

```json
{
  "name": "文章を要約",
  "value": "次の{{clipboard}}を要約してください。",
  "tags": ["AI"],
  "type": 0,
  "mode": "api",
  "options": {
    "api": "openai",
    "action": "responses-create"
  }
}
```

- API／Action選択欄には`apiDefinitions`に保存された定義を表示する
- 実行開始時に定型文の`{{clipboard}}`などを展開し、最終入力をRequest JSON内の`{{value}}`へ安全に埋め込む
- APIから返ったResponse JSONは定義された`{{value}}`の位置から結果本文を抽出し、確認画面に表示する
- 実行中、成功、認証情報不足、CORS、HTTPエラー、タイムアウト、レスポンス形式エラーを区別して表示する
- 成功結果は画面上で確認してからクリップボードへコピーできる。外部アプリへの自動貼り付けや自動送信は行わない
- API tokenなどの資格情報、認証付きURL、リクエストヘッダーはログ・エラー・バックアップ以外の画面へ出力しない

### API設定UI

- メニューに`API設定`を追加し、API定義の一覧、新規作成、編集、削除を提供する
- API設定画面に、次のAPI定義の導入方法を用意する
  - 画面上で新規作成・編集する
  - 端末のファイル選択機能からAPI設定JSONを読み込む
  - URLを指定してAPI設定JSONを取得する
  - IndexedDBに保存済みのAPI定義を一覧から選択する
- API詳細ではサービス名称、基本URL、タイムアウト、認証方式、Credential ID、非機密な`keyConfig`、Action一覧を編集する
- API token／Bearer token、Basic認証のID／PASSは資格情報入力欄から`apiCredentials`へ保存する。保存済み値は再表示しない
- 必須資格情報が未登録のAPIは実行不可とし、設定画面への導線を表示する
- 設定JSONの読み込み時は必須項目・認証方式・Action・Request／Response JSONを検証し、不正な定義を保存しない

### API関連の画面遷移

API関連画面は、既存の一覧画面を起点にしたモーダルまたは画面内パネルとして実装し、スマートフォンの戻る操作と`キャンセル`で直前の画面へ戻れるようにする。未保存の入力がある場合は破棄確認を表示する。

```text
一覧
 ├─ 左上メニュー > API設定
 │   └─ API設定一覧
 │       ├─ 新規作成 ─────────────┐
 │       ├─ ファイルから読み込み ──┤
 │       ├─ URLから読み込み ───────┤
 │       └─ 保存済みAPIを選択 ──────┘
 │               ↓
 │          API詳細
 │          ├─ 認証情報を登録
 │          ├─ Actionを追加・編集
 │          └─ 保存／キャンセル
 │
 └─ 右下＋／項目編集
     └─ 定型文編集
         ├─ plain text / template / API を選択
         ├─ APIとActionを選択
         └─ 保存／キャンセル
                 ↓
              一覧のAPI項目
                 ↓ 実行
              実行中
              ├─ 成功 → 結果確認 → コピー → 一覧
              └─ 失敗 → エラー表示 → 再試行または一覧
```

画面ごとの操作:

- `API設定一覧`: API名、設定ID、基本URL、Action数、資格情報登録状態を表示する。新規作成、ファイル読込、URL読込、編集、削除を行う
- `API詳細`: API定義の基本項目、認証方式、資格情報、Action一覧を管理する。保存成功後はAPI設定一覧へ戻る
- `Action編集`: URL、HTTPメソッド、Request JSON、Response JSONを編集する。保存成功後はAPI詳細へ戻る
- `定型文編集`: `API`を選ぶとAPI選択とAction選択を表示し、選択した定義のHTTPメソッドとURLは読み取り専用で表示する
- `実行中`: 二重実行を防ぐため実行ボタンを無効化し、API名・Action名・進行状態だけを表示する。tokenや認証付きURLは表示しない
- `結果確認`: Response JSONから抽出した結果を表示し、`コピー`、`閉じる`、`再実行`を提供する。コピー完了後は一覧へ戻る
- API設定一覧から一覧画面へ戻る場合、編集中の定型文や実行結果は失わない

### API定義JSONの読み込み

- 対象はネイティブ版と共通の単一API設定JSONとし、共通定型文JSONとは別形式として扱う
- ファイルから読み込んだAPI定義は、検証に成功した後にIndexedDBの`apiDefinitions`へ保存する
- URLから読み込んだAPI定義も、PWA側へコピーしてIndexedDBへ保存する。取得元URLの内容は変更しない
- URL取得はHTTPSを基本とし、取得先がCORSを許可していない場合は保存せずエラーを表示する
- URL取得時はリダイレクト先、応答サイズ、Content-Type、タイムアウトを検証し、認証情報付きURLやCookieを送信しない
- ファイル名・URL・JSON内の`id`が既存定義と一致する場合は、上書き前に確認する。キャンセル時は既存定義を変更しない
- API定義JSONにAPI token、Bearer token、Basic認証のID／PASSが含まれていても保存・利用せず、機密情報が含まれている旨を表示する
- API定義を読み込んだだけではAPIを実行せず、必要な資格情報をAPI設定画面で明示的に登録した後に実行可能とする
- IndexedDBからの読み込みは、保存済み定義を再利用する操作とし、ファイルやURLからの再取得は行わない

### API利用手順

利用者向けの基本手順は次の順序とする。

1. `API設定`画面でAPI定義を新規作成するか、API設定JSONをファイル・URL・IndexedDBから読み込む
2. APIの認証方式を確認し、API token、Bearer token、またはBasic認証のID／PASSを資格情報として登録する
3. 定型文の編集画面でAPIとActionを選択し、入力本文と`{{value}}`の対応を確認して保存する
4. 一覧からAPI項目を実行し、レスポンスを確認してからクリップボードへコピーする

API定義の読み込み、資格情報の登録、定型文との連携、API実行はそれぞれ独立した操作とする。資格情報が未登録の場合はAPI定義や定型文を失わず、登録画面への導線を表示する。

### 初期サンプル

`samples.json` は共通JSON形式で作成し、初回起動時、またはIndexedDB内の定型文が空の場合だけ読み込む。

- 既存の利用者データは上書きしない
- サンプル内容の変更は `samples.json` だけを編集する
- サンプルには仕事・友人への連絡文、検索用文章、AIプロンプトを含める
- 初期サンプルにはテンプレート仕様で定義する各コマンドの項目を含め、日本語項目には `テンプレ` / `ja`、英語項目には `template` / `en` を付ける
- 同じテンプレート式で結果が完全に一致する項目は、言語違いの重複を作らない
- AIプロンプトは、役割・依頼内容・出力形式・入力欄を含む構成とする

## 8. PWAとオフライン

- `manifest.webmanifest` を使用する
- `service-worker.js` でアプリ本体、初期サンプル、アイコンをキャッシュする
- 初回に正常に読み込めた後は、オフラインでもアプリ本体と保存済みデータを利用できる
- 更新時はアプリ本体とService Workerのキャッシュバージョンを同時に更新する
- メニューの `バージョンチェック` は、現在の公開URLからキャッシュを迂回して最新版の `APP_VERSION` を取得する
- 新版へ更新する場合は、既存のService Workerとキャッシュを削除して最新版を再読み込みする
- API定義の閲覧・編集、保存済み定型文の閲覧、設定バックアップの作成はオフラインで行える
- API実行、URLからのJSON取得、設定バックアップのダウンロードとリストア用ファイルの選択は、ブラウザの通信・ファイル機能が利用できる場合に限る
- オフライン時にAPI実行を開始した場合は、送信せず利用者へ状態を表示する

## 9. バージョン管理

- PWA版はネイティブ版・HTA版とは別のバージョンを持つ
- 表示用バージョンは `index.html` の `APP_VERSION` で管理する
- 画面・機能・サンプルの変更時はマイナー番号を更新する
- IndexedDBの保存形式を変更する場合は、移行方針を決めてからメジャー番号を更新する
- Service Workerのキャッシュ名は、公開するアプリバージョンに合わせて更新する

## 10. 対象外

- ネイティブ版と同じOS資格情報ストアへの保存
- ブラウザのCORS制約を回避する中継サーバー
- タスクトレイ常駐
- 他アプリへの自動貼り付け
- watchOS対応
