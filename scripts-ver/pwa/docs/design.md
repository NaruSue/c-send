# c-send PWA版 設計書

PWA版は、c-send の定型文コピー機能をブラウザ上で動かせるようにした版である。

HTA版と比べて、スマートフォン、とくに iPhone での利用を主目的とする。Windows の `mshta.exe` に依存せず、ブラウザと PWA の機能だけで使える構成を目指す。

## 目的

- バイナリを導入できない環境でも使えるようにする
- iPhone での確認・利用を前提に、タッチ操作しやすい画面にする
- 定型文を一覧からすばやくコピーできるようにする
- ローカル保存で動作し、ネットワークがなくても最低限の操作ができるようにする

## 基本方針

- 画面はスマホ基準で設計する
- ウィンドウサイズは固定とし、全画面表示を基本とする
- 設定やデータの保存は IndexedDB を使う
- カテゴリは設けず、タグで分類・検索する
- ネイティブ版の全機能は再現しない
- 設定画面は作らず、必要な内部設定のみを保持する

## HTA版との主な違い

PWA版は、HTA版の考え方を引き継ぎつつ、実行環境がブラウザになるため次の違いを持つ。

- 全画面固定のスマホUIにする
- 保存先は `IndexedDB` にする
- `mshta.exe` は使わない
- iPhone でのタッチ操作を前提に、ボタンや余白を大きめにする
- 必要に応じてインストール可能な PWA とする
- iPhoneで実現できない操作は、手動操作のフォールバックを用意する

## バージョン管理

PWA版は HTA版とは別系統として扱い、PWA版独自のバージョンを持つ。

- バージョンはアプリ内の1か所で管理する
- 表示や内部管理に使うバージョン値は、アプリ本体から参照する
- データ形式や保存仕様を変える場合はメジャーを上げる
- 画面や機能の追加・修正はマイナーを上げる

## 配布単位

PWA版は、ブラウザで開いて使える一式を1つの単位として管理する。

- `index.html`
- アプリ本体の JavaScript
- スタイルシート
- `manifest.webmanifest`
- `service-worker.js`
- `samples.json`
- アイコン類

将来的にビルドを使う場合でも、設計上は「PWA版の配布単位」を1つにまとめる。

## 画面仕様

- 画面は全画面固定
- スマホ縦持ちを基本とする
- 一覧は縦スクロールで表示する
- 画面下部に操作や状態表示を置く場合は、片手操作しやすい位置を優先する
- iPhone の安全領域を考慮する
- 画面上部にアプリアイコンとタイトルを表示する

### 画面構成

- ヘッダー
  - アプリアイコン
  - タイトル
- 検索欄
- よく使うタグの一覧
- 定型文一覧
- コピー完了などの通知表示
- 追加・編集用の入力画面
- コンテキストメニューまたは同等の操作導線

## データ保存

PWA版では、定型文と内部設定の保存に IndexedDB を使う。

### 保存対象

- 定型文データ
- ウィンドウ状態に相当する内部設定
- 必要なら最後に使った表示状態

### 保存方針

- 初回起動時は空データまたは初期データを作る
- 初期データは `samples.json` から読み込み、IndexedDBが未作成または空の場合だけ保存する
- 保存先が未作成なら自動作成する
- データ読み込み失敗時は壊れた内容を上書きしない
- 保存失敗時はエラーを表示する

### データ形式

定型文は「タイトル」「本文」「タグ」を基本にする。

```json
[
  {
    "name": "Git Status",
    "value": "git status",
    "tags": ["git", "開発"],
    "type": 0,
    "usageCount": 12,
    "lastUsedAt": "2026-07-25T12:00:00.000Z"
  }
]
```

- `name` は一覧に表示するタイトル
- `value` はクリップボードへコピーする本文
- `tags` は任意のタグ配列。1件に複数のタグを付けられる
- `type` は初期版では `0` のみ扱う
- `usageCount` はコピー回数。使用頻度順表示に使う
- `lastUsedAt` は最後にコピーした日時。同数時の並び順に使う
- `name` が空の場合は本文の先頭20文字程度から自動生成する
- 複数行テキストを許可する
- 件数上限は初期版では 100 件とする

## 主要機能

- 定型文一覧の表示
- 一覧項目のタップまたはクリックでコピー
- コピー直後にコピー本文の確認画面を表示
- 定型文の追加
- 定型文の編集
- 定型文の削除
- コピー完了通知
- タグの追加・編集・削除
- タイトル・本文・タグを対象にした検索
- タグタップによる絞り込み
- 使用回数の多い定型文を上位に表示
- 使用頻度の高いタグを上位に表示
- コピー前のクリップボード内容を追加画面へ取り込む
- アプリをホーム画面に追加して使えること

## 操作

- 一覧の項目をタップまたはクリックすると本文をコピーする
- コピー成功後は、コピーした本文を確認画面に表示する。確認画面をタップすると閉じて一覧へ戻る
- 追加画面を開いた時、ユーザー操作の直後にクリップボードのテキストを本文へ取り込む
- クリップボードの読み取りに失敗した場合は、本文欄へ手動で貼り付けられる状態にする
- 追加時は既存タグを選択するか、新しいタグをその場で追加する
- 検索欄への入力でタイトル・本文・タグを絞り込む
- タグをタップすると、そのタグを持つ項目だけを表示する
- コピーした項目は使用回数と最終使用日時を更新し、使用頻度順に再配置する
- 長押しまたはメニュー操作で追加・編集・削除を行えるようにする
- コピー完了時は短い通知を出す

## コピー処理

コピーは可能なら Clipboard API を使う。

- 通常は `navigator.clipboard.writeText()` を使う
- ブラウザ制約で使えない場合は代替手段を検討する
- iPhone では、ユーザー操作に紐づいたコピーを前提とする

## iPhoneでのクリップボード取り込み

追加画面を開く `＋` ボタンのタップをユーザー操作として、`navigator.clipboard.readText()` による読み取りを試みる。

- HTTPS環境またはホーム画面追加後のPWAで動作させる
- 読み取りに成功した場合は本文欄へ自動入力する
- iOSの許可・フォーカス・ブラウザ制約などで読み取れない場合はエラーにせず、本文欄への手動貼り付けを案内する
- アプリから別アプリを自動起動したり、別アプリへ自動貼り付けしたりする機能は対象外とする
- 利用者は、コピー後にc-sendを開いて登録し、利用時にc-sendでコピーして元アプリへ戻って貼り付ける

## 想定ユースケース

### 登録

1. Webサイトなどで登録したい文字列をコピーする
2. c-send PWAを開く
3. `＋` ボタンをタップする
4. コピー済みの文字列を本文へ取り込む
5. 必要に応じてタイトルを入力する
6. 既存タグを選ぶ、または新しいタグを追加する
7. 保存する

タイトルを入力しなかった場合は、本文の先頭20文字程度をタイトルとして保存する。

### 利用

1. 使用回数の多い定型文を上位から確認する
2. 必要に応じて、使用頻度の高いタグまたは検索欄から絞り込む
3. 定型文をタップしてコピーする
4. 元のアプリへ切り替えて貼り付ける

## iPhoneで実現する機能と制約

| 機能 | 対応方針 |
|---|---|
| タップでコピー | Clipboard APIをユーザー操作から実行する |
| コピー完了通知 | 画面上に短時間のチップを表示する |
| クリップボードから本文へ取り込み | `＋` タップ直後に読み取りを試み、失敗時は手動貼り付けへ切り替える |
| IndexedDB保存 | iPhoneのブラウザ/PWA内に保存する |
| タグ検索 | JavaScriptだけで実装する |
| 使用頻度順 | コピー回数と最終使用日時をIndexedDBに保存する |
| 元アプリへの切り替え | 利用者が手動で切り替える |
| 元アプリへの自動貼り付け | iOSおよびブラウザの制約により実装対象外 |
| PWAインストール | Safariの共有メニューからホーム画面へ追加する |

## PWA要件

PWAとして扱うため、最低限次を満たす。

- `manifest.webmanifest` を用意する
- `service worker` を登録する
- アイコンを定義する
- 画面がホーム画面追加に適している
- オフライン時でも最低限の画面表示ができる

オフライン時の挙動は、初期版では「少なくとも起動できる」ことを優先する。

### アイコン

- ホーム画面追加用のアイコンは `manifest.webmanifest` で定義する
- アプリ画面のヘッダーにも小さなアイコンを表示する
- アイコンは同一デザインでもよいが、用途ごとにサイズ違いを用意する

## 注意事項

- iPhone の Safari は通常ブラウザ表示とホーム画面追加後で挙動が異なる
- Clipboard API はユーザー操作と権限の制約を受ける
- IndexedDB のスキーマ変更時はマイグレーション方針を決めてから変更する
- 保存失敗時にデータを失わない設計にする
- 画面サイズは固定でも、端末の安全領域やキーボード表示は考慮する
