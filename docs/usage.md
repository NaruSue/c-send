# c-send 使い方

この文書は、`c-send` を初めて使う人向けの操作手順をまとめたものです。

## まずやること

1. `csend.exe` を任意のフォルダに置きます。
2. `csend.exe` を起動します。
3. タスクトレイのアイコンから本体画面を開きます。

`setting.ini` がない場合は、起動時に同じフォルダへ作成されます。

## ふつうの使い方

1. 画面上部のカテゴリを選びます。
2. 一覧から送りたい定型文をクリックします。
3. クリップボードにコピーされます。

コピー時は、カーソル付近にアプリ内 tip が表示されます。

## カテゴリの作成

カテゴリは、定型文をまとめるための単位です。

### 手順

1. カテゴリ設定画面を開きます。
2. 一覧のいちばん下にある `（追加）` を選びます。
3. 右側の入力欄に、カテゴリ名と参照先を入力します。
4. `SAVE` を押します。

### 入力する内容

- カテゴリ名
- データファイルのパス、または URL

### 参照先の例

- `samples\jp\Git.json`
- `C:\Users\example\Documents\my-category.json`
- `C:\Users\example\Documents\my-category.json`
- `https://example.com/category.json`
- `https://example.com/category.json`

## カテゴリ作成で迷いやすいところ

- `（追加）` を選ぶと、新規カテゴリとして編集できます。
- 名前か参照先が空のままだと保存されません。
- 同じカテゴリ名、同じ参照先は登録できません。
- URL を指定した場合は、保存前に接続確認が行われます。
- URL カテゴリは参照専用なので、一覧の中身は編集できません。
- 存在しないローカルファイルを拡張子なしで指定すると、保存時に `.json` が自動的に付き、JSON形式のカテゴリになります。
- `.txt` などの拡張子を明示した場合は自動変更されず、従来のテキスト形式として扱われます。
- v1.9以降は、ローカルの `.json` ファイルと、JSON形式を返すURLをJSONデータとして扱います。

## テンプレート

JSONデータの `template` 項目では、日時やクリップボードの内容を展開してからコピーできます。

詳しい作成手順と記法は、[テンプレートの使い方](./template-usage.md) を参照してください。

## API機能を追加する

API機能は、知識のある利用者が設定JSONを直接作成する方法と、AIに設定JSONと導入手順を作成してもらう方法に対応しています。

初めて追加する場合は、次の資料をAIへ渡す方法を推奨します。

1. [API設定JSON仕様](./api/config-spec.md)
2. 利用したいAPIの公式ドキュメント、または公式ドキュメントのURL

利用したい機能やActionが決まっている場合は、その希望も短く伝えます。独自認証など通常と異なる仕様の場合だけ、[API認証方式仕様](./api/auth-spec.md)も追加します。

[API設定JSON仕様](./api/config-spec.md)に、そのまま利用できるプロンプトがあります。AIは次の内容をまとめて出力します。

- `api`フォルダへ保存する設定JSON
- 必要なtoken、ID、PASSの種類
- Windows Credential Managerへ登録するための画面操作
- カテゴリへAPI項目を追加する手順
- 初回の動作確認手順

token、APIキー、ID、PASSの実際の値はAIへ送らず、c-sendのAPI詳細画面から登録してください。

### AIで追加する基本手順

1. AIの新しいチャットへ[API設定JSON仕様](./api/config-spec.md)を添付します。
2. 利用したいAPIの公式ドキュメント、または公式URLを添付します。
3. 「API設定JSON仕様内のプロンプトに従い、○○を行う設定と導入手順を作成してください」と依頼します。
4. AIが質問してきた場合は、利用したい機能、Action、モデルなどを回答します。tokenやパスワードは回答しません。
5. AIが出力したJSONだけを、`csend.exe`と同じ場所にある`api`フォルダへ保存します。
6. c-sendを再起動し、システムメニューの「API」から追加された設定を確認します。
7. 必要なtoken、ID、PASSをAPI詳細画面から登録します。
8. カテゴリの「（追加）」でAPIとActionを選び、実行用プロンプトを登録します。
9. 機密情報を含まない短い文章で動作確認します。

依頼文の記入例、JSONの保存方法、エラー時の確認箇所、仕様変更時の更新方法は、[API設定JSON仕様の「AIでAPI設定を追加する手順」](./api/config-spec.md#aiでapi設定を追加する手順)を参照してください。

GitHubを参照できるAIでは、仕様ファイルの添付に代えて[c-send公開リポジトリ](https://github.com/NaruSue/c-send)を指定できます。利用中のアプリと仕様を合わせるため、可能なら同じリリースタグの`docs/api/config-spec.md`を指定してください。URLを参照できないAIには、配布物のファイルを直接添付します。

## 公開サンプルカタログ

共通JSON形式のサンプルは、GitHubのRaw URLで公開カタログとして管理できます。

### ネイティブ版で直接参照する

ネイティブ版では、GitHubのRaw URLをカテゴリの参照先に指定できます。URLカテゴリは読み取り専用で、GitHub上の最新内容を参照します。

例:

```text
https://raw.githubusercontent.com/NaruSue/c-send/master/samples/jp/テンプレート.json
```

### ローカルで編集する

公開カタログのJSONをダウンロードし、ローカルJSONとして追加すれば、通常の定型文と同じように編集・削除できます。ダウンロード後の変更はGitHub上のカタログには反映されません。

PWA版では、メニューの「URLから追加」からRaw URLを入力して取り込めます。取得先がCORSを許可している必要があります。取り込み後はPWAの端末内データとして自由に編集・削除できます。

## 並べ替えと削除

- `up` と `down` でカテゴリの順番を変えられます。
- `Delete` でカテゴリを削除できます。
- 削除してもデータファイル自体は消えません。

## よくある見え方

- `URL` と付いたカテゴリは URL 参照です。
- `RO` と付いたカテゴリは読み取り専用です。

## 補足

- カテゴリの設定は `setting.ini` の `[category]` に保存されます。
- 詳しいキー仕様は [setting.ini 仕様](./setting-ini-spec.md) を参照してください。
