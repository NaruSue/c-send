# c-send 基本共有ドキュメント

この文書は、c-send関連のアイデア出し・仕様整理・実装で共通参照するための概要です。
詳細仕様は、このリポジトリ内の各設計書を正とします。

## 1. 全体像

c-sendは、定型文・テンプレートを作成、保存、展開、コピー、共有するためのアプリ群です。

大きく分けて、次の4つを区別します。

| 分類 | 役割 |
| --- | --- |
| ネイティブアプリ | Windows上で動くc-send本体。ローカルの定型文、クリップボード、テンプレート展開、外部API連携を扱う |
| Webアプリ / PWA | `https://narusue.github.io/c-send.pwa/` のc-send.web。旧URLは既存ユーザーの更新経路として残す。テンプレートを端末内に保存し、オフラインでも使う。ログイン中は項目ごとに許可した同期やアカウントバックアップも利用できる |
| テンプレート管理 | `https://loose.bz/c-send/t/` のポータル内セクション。テンプレート閲覧・管理・審査・公開を扱う |
| ポータル | `https://loose.bz/c-send/`。c-sendの公式サイト。Webアプリとテンプレート管理セクションを案内 |
| API | `https://loose.bz/c-send/api/`。Webアプリと共有サイトを接続し、認証やテンプレート保存・同期を扱う |

## 1.1 現行・旧版・将来案の区別

このリポジトリには、現行の実装、旧版の参照実装、設計中の将来案が同居しています。文書や会話では、必ずどの区分の話かを明記します。

| 区分 | 対象 | 扱い |
| --- | --- | --- |
| 現行 | ルート直下のネイティブc-send本体、`web/`配下の共有サイト・API、`web/pwa/`配下の公開PWA | 現在の実装・公開対象。変更時は動作確認と関連ドキュメント更新を行う |
| 旧版・参照 | `scripts-ver/hta/`、`scripts-ver/pwa/`、`scripts-ver/library-site/` | 旧版または既存挙動の参照元。現行仕様と一致するとは限らず、ここを変更して現行版が変わるとは限らない |
| 設計・将来案 | `docs/`内で「設計」「将来」「案」「未実装」と明記された内容 | 合意済みの設計または検討事項。実装済みとは扱わない |

特に `scripts-ver/pwa/` は、現行`.web`の初期機能や挙動を考える際の参照資産であり、現行`.web`そのものではありません。`docs/`の設計書でも、実装済み・計画・未実装を分けて確認します。

## 2. 名前とURLの対応

| 名前 | 位置付け | 現在のURL |
| --- | --- | --- |
| `.org` | c-sendのポータルサイト。各機能への入口 | `https://loose.bz/c-send/` |
| `.web` | テンプレートを利用するWebアプリ | `https://narusue.github.io/c-send.pwa/` |
| `.web.pwa` | `.web`をPWAとしてインストール・起動する状態。別サービスではない | `.web`と同じアプリ・データを利用 |
| `.tmp` | ポータル内のテンプレート閲覧・管理・公開セクション。アカウントとプロフィールはポータル共通 | `https://loose.bz/c-send/t/` |
| `.api` | `.web`や互換クライアント向けのAPI。`.tmp`とDB・バックエンドの一部を共有 | `https://loose.bz/c-send/api/` |
| `.pea` | リポジトリ内で定義を確認できていない。名前・役割は要確認 | 未確定 |

`.web`と`.tmp`は同じc-sendポータル内の画面・役割です。`.web`はテンプレートを使うアプリ、`.tmp`はテンプレート管理セクションです。登録・ログイン・プロフィールはポータル共通のアカウント機能として扱います。

## 3. 保存先の考え方

- **ローカル保存**: 標準の保存先。端末内に保存し、ログインだけで既存項目をサーバーへ送らない。オフライン利用できる。
- **項目ごとのアカウント同期**: ログイン中に利用者がアップロードを許可した項目を、認証付きAPIで非公開の下書きとして同期する。公開は共有サイトの審査・公開フローを通す。
- **アカウントバックアップ**: PWAから明示的に保存・復元する。公式サンプルとテンプレートサイト参照項目は対象外。
- **公開データ**: ポータル内のテンプレート管理セクションが正本。PWAは必要に応じて取得・キャッシュする。
- `.web.pwa`は`.web`と別データを持つ別アプリではなく、同じWebアプリのPWA利用形態。

## 4. 共通データ

ネイティブ版、HTA版、PWA版で使うJSON形式は `docs/data-file-spec.md` を正とします。

- ルートはオブジェクト
- `format` は `c-send-pwa-backup`
- 整数の `version`、`versionMinor`、`versionPatch` を持つ（現行の形式定義は `1.1.0`）
- 定型文は `items` 配列に格納
- 各項目は `name`、`value`、`type`、`mode` などを持つ
- `.tmp`のサイト管理名と、c-sendアプリで表示する項目タイトルは別概念

## 5. 仕様を更新するときの原則

1. 名前・URL・役割を変更する場合は、この文書と詳細設計書を同時に更新する。
2. `.web`、`.tmp`、`.api`の責務を混同しない。
3. 公開データ、非公開データ、端末内データの保存先と正本を明記する。
4. `.pea`の意味は、正式な定義が確認できるまで新しい仕様で前提にしない。
5. 実装済みの内容と将来案を分けて書く。
6. 旧版・参照実装の仕様を、現行版の仕様として引用しない。パス、URL、リリースノート、実装状態を一緒に確認する。
7. 共有資料では、見出しまたは表に「現行」「旧版・参照」「将来案」の区分を付ける。

## 共通JSON 1.1.0との対応（仕様定義）

共通形式の正本は [共通JSONデータ形式仕様](data-file-spec.md) です。独自の互換アプリも同じ形式を利用できます。

- 形式バージョンは整数の `version`、`versionMinor`、`versionPatch` で表し、現行定義は `1.1.0`。旧データの省略されたマイナー・パッチは `0` と扱います。
- ファイル全体の補足情報は `option`、項目ごとの補足情報は `items[].option` に置きます。作成者は `author`、更新履歴は `history`、アプリ固有の情報は `apps` に記録できます。
- 履歴は変更日時・説明に加え、変更前の本文 `previousValue`、差分 `diff` と形式識別子 `diffFormat` を任意で持てます。表示・記録・復元はアプリ側が判断します。
- `option` は利用時に解釈しなくても構いませんが、保存し直す際は未知の情報も保持します。既存の `items[].options` は動作設定であり、補足情報の `option` とは別です。
- 履歴なし出力では、元データを保持し、出力用コピーの `option.history` と `items[].option.history` だけを削除します。

これは共通形式の定義です。この文書の対象アプリで、情報の保持・履歴管理・履歴なし出力が実装済みであることを示しません。対応には実装と検証が必要です。

## PWA保守情報の補足（2026-11-05）

現行実装は `web/pwa/`、配信版は0.1.85。GitHub Pagesと互換URLはいずれも `web/pwa/` を公開元とし、`scripts-ver/pwa/` は旧版・参照用として配信に使わない。接続先一覧の公式アカウント状態と、ポータルのCookieセッションを区別する。
PWA固有の補助機能は [開発・保守用仕様](pwa-easter-egg.md) で管理し、共通JSONの `items` や `option` にゲーム記録を混ぜない。自己ベスト・解放は公式ユーザー別の端末内データで、共通テンプレートバックアップや同期対象ではない。
診断ログのアップデート時初期化は [次回更新項目](pwa-next-update.md) に記載した実装済み事項。端末内バッファのみを対象とする。
