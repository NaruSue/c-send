# c-send 共通JSONデータ形式仕様

この文書は、c-sendのネイティブ版・HTA版・PWA版で共通して使用するJSONデータファイルの仕様を定義する。

## 1. 方針

- JSONデータファイルの形式は、3つの版で統一する
- 新規作成・保存するJSONは、必ず本仕様の形式とする
- 従来の配列ルートJSON形式は廃止し、本仕様では受け付けない
- JSON以外の従来の3行1レコード形式は、ネイティブ版の既存仕様として別途扱う
- JSON形式の詳細は、各版の設計書ではなく本仕様を正とする

## 2. JSONファイルの構造

JSONファイルはUTF-8（BOMあり・なしのどちらも可）で保存する。ルート要素はオブジェクトとする。

```json
{
  "format": "c-send-pwa-backup",
  "version": 1,
  "createdAt": "2026-07-27T00:00:00.000Z",
  "categoryName": "仕事",
  "items": [
    {
      "name": "Git Status",
      "value": "git status",
      "type": 0,
      "mode": "plain",
      "tags": ["Git"],
      "usageCount": 3,
      "lastUsedAt": "2026-07-27T00:00:00.000Z"
    }
  ]
}
```

### ルートプロパティ

| プロパティ | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `format` | 文字列 | 必須 | 固定値 `c-send-pwa-backup` |
| `version` | 整数 | 必須 | JSON形式のバージョン。初版は `1` |
| `createdAt` | ISO 8601文字列 | 必須 | バックアップファイルが作成された日時 |
| `categoryName` | 文字列 | 任意 | ファイル単位のカテゴリ名 |
| `items` | 配列 | 必須 | 定型文の配列 |

### メタデータ

将来追加されるメタデータは、既存の版が利用できなくても、可能な限り保持して保存する。現行のPWAバックアップでは `createdAt` を使用する。

`categoryName` は、HTA版でJSONファイル単位のカテゴリを表示するために使用する。値がない場合、HTA版は必要に応じて配置ディレクトリ名またはファイル名を表示用の代替値とする。

### 1件の項目

| プロパティ | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `name` | 文字列 | 必須 | 一覧に表示する名前。空文字は不可 |
| `value` | 文字列 | 必須 | クリップボードへ送る本文。複数行可。空文字を許可 |
| `type` | 整数 | 必須 | データ種別。現時点では `0`（テキスト）のみ |
| `mode` | 文字列 | 必須（旧データは省略可） | `value` の処理方法。`plain`、`template`、`counter` のいずれか |
| `options` | オブジェクト | 任意 | `mode` に固有の設定。詳細は各機能の仕様で定義する |
| `tags` | 文字列配列 | 任意 | タグ。未指定時は空配列として扱う |
| `usageCount` | 0以上の整数 | 任意 | 使用回数。未指定時は `0` として扱う |
| `lastUsedAt` | ISO 8601文字列または空文字 | 任意 | 最終使用日時。未指定時は空文字として扱う |
| `sourceName` | 文字列 | 任意 | 項目を取り込んだ元ファイル名または元URL |

- 共通JSON形式では、`items` の件数上限を定めない
- 各版で件数制限を設ける場合は、各版の設計書に定義する
- `type` は現時点では `0` に固定する。将来の出力種別追加時に値を拡張する
- `mode` は値の処理方法を表し、次の値を使用する
  - `plain`: `value` をそのまま扱う
  - `template`: `value` を汎用テンプレートとして扱う。外部リストや日時計算などの機能を含む場合がある
  - `counter`: `value` にカウント処理を適用する。仕様上の予約値とし、現行UIでは選択できない
- 新規作成・保存する項目には `mode` を設定する
- `mode` がない既存項目は、後方互換性のため `plain` として扱う
- `options` の内容は `mode` ごとの仕様で定義し、本仕様では共通の入れ物だけを定義する
- 共通項目以外の項目プロパティは、読み込み後の保存で失わないようにする
- 各版で表示・利用しない項目も、データの互換性維持のため保持する
- `sourceName` はPWAで複数ファイルやURLから追加した項目の出所を記録するために使用する
- ファイルから追加した場合はファイル名、URLから追加した場合はURLを `sourceName` に保存する
- 既に `sourceName` が設定されている項目をバックアップから読み込む場合は、既存値を保持する

## 3. 形式判定とエラー

- `.json` ファイル、またはJSONとして取得したURLは本仕様の形式として読み込む
- `format` が `c-send-pwa-backup` 以外、または `version` が対応外の場合は読み込みエラーとする
- ルートが従来の配列形式の場合も、旧JSON形式として読み込まず、形式エラーとする
- ルートがオブジェクトでも必須プロパティが不足している場合は形式エラーとする
- JSONの構文不正、型不正、件数超過、必須項目不足は形式エラーとする
- 読み込みエラー時は、既存データを空データで上書きしない

## 4. 読み書き

- ローカルJSONは、追加・編集・削除後も本仕様の形式で上書き保存する
- PWAのバックアップとリストアも本仕様のJSONを使用する
- ネイティブ版のURLカテゴリで取得したJSONは参照専用とし、編集・保存は行わない
- PWA版のURL追加では、取得した項目を端末内へコピーして編集・保存する

## 7. 公開カタログとしての利用

共通JSON形式のファイルは、GitHubなどで公開するサンプルカタログとして利用できる。

- GitHub上のJSONは、Raw URL（`raw.githubusercontent.com`）で公開する
- ネイティブ版は、Raw URLをURLカテゴリとして登録し、公開ファイルを直接参照できる
- URL参照は読み取り専用とし、元のGitHubファイルは変更しない
- 手元で編集したい場合はJSONファイルをダウンロードし、ローカルファイルとして追加する
- ローカルへ追加した後は、通常のデータとして自由に編集・削除できる
- 取得元を記録する場合は、項目の `sourceName` にURLまたはファイル名を保存する
- カタログへサンプルを追加するときは、言語や用途をタグで区別し、同じ結果になる重複項目を作らない

PWA版もURLから共通JSONを追加できる。取得先がCORSを許可している必要があり、GitHub Raw URLは公開カタログの取得先として利用できる。URLから追加したデータは端末内へコピーされ、取り込み後は編集・削除できる。
- バックアップファイルの作成元を示す追加情報は、将来の仕様で定義する

## 5. 従来の3行1レコード形式

JSON以外のデータファイルについては、ネイティブ版の既存仕様である3行1レコード形式を維持する。

```text
name
type
value
```

この形式は本仕様のJSON形式とは別形式であり、HTA版・PWA版の共通JSONデータ交換には使用しない。
