# API・AI対応 設計メモ

この文書は、次回以降のAPI対応版・AI対応版を実装するときの検討事項を記録する。

## 対象版

- ネイティブ版：フル機能としてAPI・AI対応を検討する
- PWA版：スマートフォンでの利用を中心に、通信できる場合だけAPI・AI機能を利用する
- HTA版：API・AI対応の対象外。シングルカテゴリとローカルJSON運用を基本とする

## API結果の基本動作

1. API実行開始時のクリップボード内容を保持する
2. API結果はユーザーに見せる一覧を作らず、内部メモリ上の結果リストに保持する
3. API結果が返った時点で、現在のクリップボード内容を再取得する
4. 開始時と現在の内容が同じ、または現在の内容が空の場合だけ、API結果をクリップボードへ自動コピーする
5. 内容が変更されていて空でない場合は、現在のクリップボードを上書きしない
6. 完了したAPI項目の結果アイコンから結果をクリップボードへコピーできるようにする

### クリップボード比較

- 取得できる場合は、開始時の内容と結果取得時の内容を比較する
- 比較は内容そのもの、または内容のハッシュ値で行う
- PWAで権限やブラウザ制約により読み取れない場合は、安全側で自動コピーしない
- API結果は、条件を満たした場合に常に自動コピーする
- API結果をコピーする直前にも、必要に応じて再確認する
- クリップボードを読み取れない場合は、安全側で自動コピーしない

## API項目ごとの状態と直近結果

初期実装ではユーザー向けの結果一覧画面は作成しない。ただし、内部メモリ上に結果リストを保持し、各API項目の状態、直近の結果、エラー、再コピーに利用する。

- 実行中・完了・失敗の状態を表示する
- 実行日時、結果本文、HTTPステータス、エラー内容を保持する
- 完了した項目の結果アイコンから結果をコピーできる
- 結果履歴や複数結果の一覧表示は後回しにする

## 待機・再試行

- 通信中は待機状態を表示し、他の定型文操作を妨げない
- タイムアウトを用意する（初期値120秒）
- 初期実装では自動再試行しない
- 将来はエラー内容を判別して再試行する
- APIが非同期ジョブを返す場合は、ジョブIDを使って状態を確認する
- 「処理中」と「通信失敗による再試行可能」を区別する

## APIキー

- APIキーは各端末で管理する
- GitHub、共通サンプルJSON、バックアップへAPIキーを保存しない
- ネイティブ版は端末ローカル設定を使用する
- PWA版は端末のブラウザ内設定を使用する
- APIキーの表示・変更・削除を行えるようにする

## 実装順序

1. API接続、待機、120秒タイムアウト、失敗
2. API項目の状態表示と手動コピー
3. クリップボードの開始時・結果取得時比較
4. AI向けのプロンプト実行と結果表示
5. 結果履歴や前回結果の再利用
